【史鉴统一网站】团队使用说明（云端同步版）

一、你们最终只需要记住一个地址

http://主机地址:8772/史鉴团队网站.html

成员 2（技术与部署）在一台电脑启动服务后，把黑色窗口里显示的“队友访问”地址发到群里。三个人以后都打开这个同一个地址，建议、史料和版本会写入同一份云端数据库。修改程序后只需更新服务器文件，大家刷新网页即可，不需要反复收发 ZIP。

二、第一次启动

1. 解压项目包。
2. 在解压目录双击“启动史鉴团队网站.bat”。
3. 浏览器会打开本机入口；把窗口打印的局域网地址发给成员 1 和成员 3。
4. 三个人连接同一局域网时，可以直接访问该地址。127.0.0.1 只代表启动服务的那台电脑，不能发给队友。

三、统一入口里的三个页面

1. 历史智能体：证据问答、史料检索、时间线、材料题训练和答案反馈。服务器能连接 AI 时使用真实模型；没有 AI 配置时明确显示离线演示。
2. 团队建议中心：提交功能建议、史料纠错、模型错误、验收标准和演示问题。在线时每条记录直接保存到共享数据库，其他成员刷新或等待自动同步即可。
3. 使用说明：查看文件用途、启动方式和协作边界。

四、管理员如何更新云端内容

在同一个网址打开“史鉴云端管理.html”（例如 http://主机地址:8772/史鉴云端管理.html）。只有管理员使用此页：

1. 输入管理员令牌。本地启动脚本会显式设置 local-dev；公网部署必须由成员 2 设置新的 SHIJIAN_ADMIN_TOKEN，服务器不会为公网隐式生成默认令牌。
2. 修改系统提示词或项目版本后点“保存 AI 规则”。
3. 成员 3 核验史料后，在“云端史料”区域编辑并点“保存全部史料”。
4. 回到统一入口并刷新，智能体会读取最新配置和史料。

五、真实 AI 的配置

API 密钥只能放在运行服务器的环境变量中，不写进 HTML、不发进群、不放进项目 ZIP。成员 2 在启动服务器前设置：

SHIJIAN_BASE_URL = 中转站或 OpenAI 兼容接口的地址（通常以 /v1 结尾）
SHIJIAN_API_KEY = API 密钥
SHIJIAN_MODEL = 模型名称
SHIJIAN_ADMIN_TOKEN = 管理员令牌
（如自定义端口，可设置 SHIJIAN_PORT；如从其它域名调用 API，可设置逗号分隔的 SHIJIAN_ALLOWED_ORIGINS。默认只允许同源访问。）

未设置前三项时，网站仍可用固定案例和离线流程演示，但页面会明确标注未连接真实 AI。

六、展示流程

1. 启动“启动史鉴团队网站.bat”。
2. 在历史智能体输入准备好的固定问题，展示“识别问题→检索史料→引用→回答→反馈”流程。
3. 打开团队建议中心，提交一条示例建议，展示它如何出现在共享看板。
4. 打开云端管理页（只向评委展示必要部分），说明史料和规则修改后刷新即同步。
5. 网络异常时，使用页面里的固定离线案例、截图和文档完成备用展示。离线模式不能冒充真实模型生成。

七、网络与安全边界

- 127.0.0.1 只能本机访问；192.168.x.x 等局域网地址只能在同一网络访问。
- 如果要让校外任何人使用，需要把服务器部署到公网，并配置 HTTPS、登录或邀请码、管理员权限、限流和数据库备份。
- 启动脚本仅为本机/局域网演示显式设置 local-dev；公网必须改用强令牌，也不要把 API 密钥放到浏览器设置或网页文件。
- 当前原型适合课程开发和局域网展示；正式公网使用前应进行安全审查。
- 服务器会拒绝过大的 JSON、异常字段和重复史料 ID；管理写入必须带管理员令牌。公网部署仍需补充登录、限流和备份。

八、日常协作

成员 1 维护需求优先级、测试题和验收记录；成员 2 维护服务器、AI 接口和演示；成员 3 核验史料、范围和标准答案。Codex / GPT-6 Astra 负责把建议转成实现、测试和文档，但三位成员必须理解并最终核验结果。
