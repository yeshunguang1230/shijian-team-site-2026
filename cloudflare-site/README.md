# 史鉴 · 云端团队网站

固定入口：[史鉴团队网站](https://shijian-team-site-public.pages.dev/)

下述功能与边界对应本仓库代码；线上版本及实测记录由部署记录确认。

## 使用方式

- 游客：直接访问公开首页和学习空间，只能读取已发布史料。
- 三名开发者：分别在 `/login.html` 使用独立账号，首次必须修改临时密码。登录后进入 `/admin.html`，管理共享史料、团队建议和规则设置。
- 导入资料：后台「共享史料」选择 PDF、Word（.docx）、TXT 或 Markdown，检查提取出的正文、补充出处，再明确点击「保存草稿」或「发布到前台」。无需编写 JSON。
- 三人共用一份云端数据库，各自使用自己的账号；自动检查更新不等于自动保存输入，也不进行多人逐字合并。
- 当前尚未配置模型服务，学习空间明确标识规则演示。网站、登录、资料和建议功能不依赖模型服务。

## 协作、冲突与本机恢复稿

后台页面可见时约每 25 秒检查一次云端版本；返回页面或网络恢复时也会尝试检查。可以随时点击「立即检查更新」，或使用资料列表、建议看板的刷新按钮。检查频率会受浏览器与网络状态影响，不保证每次更改都在 25 秒内显示。

检查会更新有变化的列表并提示版本冲突，**不会自动上传编辑内容，也不会用队友的版本覆盖当前编辑框**。资料正文、建议提交和规则更改都需要明确保存或提交；只有发布后的史料进入游客知识库。

史料、建议状态和规则设置都有版本保护。使用旧版本保存时会提示冲突，避免悄悄覆盖队友的修改。先保留自己的内容，再读取最新版本、比较合并后保存；「读取最新版本」或「载入最新规则」是主动替换编辑框的操作，需要留意提示。网络中断而未收到保存确认时，输入会保留；恢复连接后先核对记录，按提示重试。

「共享史料」编辑时会尝试保留**当前账号在本浏览器的恢复稿**。它不是云端草稿，不会出现在队友或另一台设备上；恢复到编辑框后仍需点击保存。正常退出登录会清除当前账号的本机恢复稿；若本地存储不可用、空间不足或清除失败，页面会给出提示，请先保存到云端或另行复制重要内容。规则和建议输入没有这套恢复稿功能，不要把页面内保留误认为持久保存。

团队建议可按当前筛选复制或下载 TXT 摘要，包含记录编号、版本、成员署名、内容、验收与进度。导出是列表快照；先刷新看板再导出才能包含刚读取的更新。复制受限时显示可全选的文字，不会自动发送给任何人。

## 文档导入

导入先在浏览器提取和预览正文，不会自动上传或发布。PDF 显示逐页提取进度；Word 显示提取阶段。文字 PDF 会保留「第 N 页」标记；部分页面没有提取到文字时，会提示数量，可能是空白页或扫描图片，必须对照原件检查。整份文档没有可提取文字时，会明确报错。

云端保存提取出的正文与填写的来源信息，**不保存原附件，不保留图片和原排版，也不提供 OCR 文字识别**。扫描件需要先在其他工具中识别，再检查并导入文字。请自行保留原文件。单文件最大 10 MB，PDF 最大 200 页，正文最大 20 万字符；旧版 `.doc` 需先转换成 `.docx`。

## 学习空间的实际边界

正式资料检索只使用已发布正文；未发布草稿不会参与。尚无公开资料时，页面会明确使用内置演示材料，不把它们当作已核验史实。

长文按段落、已有页码标记和字符窗口切分，再按词匹配排序，并控制材料总长度。**这是文本检索，没有语义向量检索或语义搜索**，换用同义词可能找不到原文。命中文档后部时使用实际命中片段，不再固定截取文档开头。

证据面板展示本次选中的完整片段、来源 ID、正文位置和原文已有页码标记；只有实际调用模型后才标为提供给模型的材料。缺少页码标记时不猜测页码。材料题的出题、页面展示与批改使用同一份片段快照。

当前流程由用户选择功能后固定执行，不宣称模型自主规划或选用工具。真实 AI 尚未配置时，只显示规则演示、原文片段和固定提示；规则反馈不判断史实真假，不给正式成绩。练习记录仅保留在当前学习页面，尚不跨设备保存。

## 架构

Cloudflare Pages 提供固定网址和静态页面，并同源代理 `/api/*` 到 Cloudflare Worker。Worker 提供认证、权限校验、资料和建议接口，D1 存储用户、会话、史料和团队记录。完成部署后，网站与云端数据不依赖个人电脑持续开机。

`public/` 是公开资源；`src/` 是后台代码；`pages/_worker.js` 是 Pages 代理；`migrations/` 是数据库迁移；`scripts/` 是部署辅助脚本。构建只复制公开资源及 Pages 代理，不上传账号文件、数据库备份、项目私有文档或开发环境。

## 账号与安全

仅创建三个开发者账号，没有公开注册入口。账号文件在工作区私有目录中单独保存，每人只接收自己的一份。密码使用带随机盐的 PBKDF2-SHA256 哈希；D1 不保存明文密码。会话使用 Secure、HttpOnly、SameSite=Lax Cookie，数据库仅保存会话令牌哈希。改密撤销该账号旧会话，退出撤销当前会话。

私有 API 在服务端检查身份；首次改密前不能访问后台数据。旧版团队邀请码和管理员令牌已不再接受。跨站写请求会检查来源；登录有速率限制。新增史料默认草稿，只有明确发布的内容对游客开放。升级保留旧数据，旧史料暂存为草稿。

## 开发与验证

```powershell
npm ci
npm run check
npm run check:e2e
npx wrangler deploy --dry-run
```

检查命令包含接口错误处理、账号隔离、本机恢复稿、长文片段检索与材料一致性、后台协作流程等测试。端到端测试使用独立本地 D1 和测试账号，检查三个账号、强制改密、会话轮换/退出、旧令牌无效、草稿保护、版本冲突、发布可见、作者身份和重启持久化。具体运行结果以本轮验收记录为准，测试文件存在不等于已经通过本次部署验收。

## 部署

现有 D1 已绑定于 `wrangler.json`，正常更新无需新建数据库或重新创建账号。

```powershell
npx wrangler d1 migrations apply shijian-team-db --remote
npx wrangler deploy
npx wrangler deploy --name shijian-team-site-2026-pages
npm run build:pages
$pagesDirectory = (Get-Content .pages-build/latest.txt -Raw).Trim()
npx wrangler pages deploy $pagesDirectory --project-name shijian-team-site-public --branch main --commit-dirty=true
```

两个 Worker 共用数据库，发布安全更新时需要同时升级，避免旧入口继续使用旧规则。Pages 的固定域名已列在 Worker 允许来源中；启用新域名时需同步配置。

首次账号初始化通过 `scripts/prepare-accounts.mjs` 在部署目录之外生成私有文件，再将该私有 seed SQL 导入 D1；不要重复生成或提交到 Git。已有账号的密码不能从数据库还原，遗失时由维护者安全重置。

真实 AI 需要在 Worker 服务端分别配置 `SHIJIAN_BASE_URL`、`SHIJIAN_API_KEY`、`SHIJIAN_MODEL`。密钥不能写进网页、公开仓库或群聊。配置后仍须实际验证模型调用，不能仅凭配置状态宣称 AI 可用。

模型代理仅允许已完成首次密码设置的开发者调用。服务端默认输出预算为 2500 tokens，可请求 1–4000 的整数；上游必须支持兼容的 `max_tokens` 参数。25 秒限时覆盖响应头与正文读取，正文累计最多 2 MiB。上述是实现的边界，不能代替选择具体中转服务后的兼容性验证。

公网可访问性受各设备的网络路径和服务状态影响。本版通过固定 Pages 域名访问，不要求三人在同一局域网。跨设备展示前仍应在展示现场网络实测。
